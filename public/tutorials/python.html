Argument Patterns

Closures & LEGB Rule

# LEGB: Local → Enclosing → Global → Built-in
def make_counter(start=0):
    count = start          # Enclosing scope
    def increment(step=1):
        nonlocal count    # modify enclosing variable
        count += step
        return count
    return increment

counter = make_counter(10)
print(counter())   # 11
print(counter(5)) # 16

functools Toolkit

from functools import lru_cache, partial, wraps

# LRU cache — memoization
@lru_cache(maxsize=128)
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)

# partial — freeze some arguments
power_of_2 = partial(pow, 2)
print(power_of_2(10))  # 1024

# wraps — preserve metadata in decorators
def my_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("before")
        result = func(*args, **kwargs)
        print("after")
        return result
    return wrapper

Classes & OOP

Deep OOP knowledge — dunder methods, slots, ABC, and the difference between dataclass/namedtuple/TypedDict — is a hallmark of senior Python developers.

Dunder Methods (Magic Methods)

class Money:
    def __init__(self, amount: float, currency: str = "USD"):
        self.amount = amount
        self.currency = currency

    def __repr__(self):  # for developers (repr(obj))
        return f"Money({self.amount!r}, {self.currency!r})"

    def __str__(self):   # for users (str(obj))
        return f"{self.currency} {self.amount:.2f}"

    def __eq__(self, other):
        if not isinstance(other, Money): return NotImplemented
        return self.amount == other.amount and self.currency == other.currency

    def __hash__(self):  # required if __eq__ is defined
        return hash((self.amount, self.currency))

    def __add__(self, other):
        if self.currency != other.currency:
            raise ValueError("Cannot add different currencies")
        return Money(self.amount + other.amount, self.currency)

    __slots__ = ["amount", "currency"]  # saves ~50% memory vs __dict__

Abstract Base Classes

from abc import ABC, abstractmethod

class Repository(ABC):
    @abstractmethod
    def get(self, id: int): ...
    @abstractmethod
    def save(self, entity): ...

class UserRepository(Repository):
    def get(self, id): return db.query(User, id)
    def save(self, entity): db.add(entity)
Interview Tip
If you define __eq__, Python sets __hash__ to None (making the object unhashable). You MUST explicitly define __hash__ if you want the object in sets/dicts.

Q: What is the primary benefit of using __slots__ in a Python class?

✓ Correct! __slots__ replaces the per-instance dictionary with a fixed-size array, saving 40–50% memory for data-heavy objects.

Decorators & Method Types

Decorators are one of Python's most powerful patterns — understanding how to write parameterized and class-based decorators is essential.

Decorator Anatomy

import time
from functools import wraps

# Parameterized decorator factory
def retry(times=3, exceptions=(Exception,)):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    if attempt == times - 1: raise
                    time.sleep(2 ** attempt)
        return wrapper
    return decorator

@retry(times=5, exceptions=(IOError,))
def fetch_data(url): ...

@classmethod vs @staticmethod vs @property

class User:
    _registry = {}

    def __init__(self, name, email):
        self.name = name; self.email = email

    @classmethod
    def from_dict(cls, data: dict) -> "User":
        # Alternative constructor — cls enables subclassing
        return cls(data["name"], data["email"])

    @staticmethod
    def validate_email(email: str) -> bool:
        # No self/cls — pure utility function namespaced to class
        return "@" in email

    @property
    def display_name(self) -> str:
        return self.name.title()

    @display_name.setter
    def display_name(self, value):
        self.name = value.lower()

Q: Why should you use @functools.wraps in a decorator?

A) It makes the decorator run faster
B) It prevents the decorator from being applied twice
C) It preserves the wrapped function's __name__, __doc__, and metadata
D) It automatically handles exceptions
✓ Correct! Without @wraps, the wrapper replaces the original function's metadata — breaking introspection, docs, and debugging.

Descriptors & Properties

Descriptors are the mechanism behind property, classmethod, staticmethod, and ORM fields — mastering them shows deep Python expertise.

Descriptor Protocol

# Data descriptor — defines __set__ (takes priority over instance __dict__)
class Validated:
    def __set_name__(self, owner, name):
        self.name = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None: return self  # class access
        return getattr(obj, self.name, None)

    def __set__(self, obj, value):
        if not isinstance(value, (int, float)) or value < 0:
            raise ValueError(f"{self.name} must be non-negative number")
        setattr(obj, self.name, value)

class Product:
    price = Validated()
    quantity = Validated()

    def __init__(self, price, quantity):
        self.price = price          # triggers Validated.__set__
        self.quantity = quantity

Non-data vs Data Descriptors

TypeDefinesPriority
Non-data descriptor__get__ onlyInstance __dict__ wins
Data descriptor__get__ + __set__ (or __delete__)Descriptor wins over instance
Real-world Use
SQLAlchemy's Column(), Django's models.Field, and Pydantic's field validation all use the descriptor protocol under the hood.

Q: What makes a descriptor a "data descriptor"?

A) It defines __set__ or __delete__
B) It stores data in the instance dictionary
C) It only defines __get__
D) It inherits from a base Descriptor class
✓ Correct! A data descriptor defines __set__ and/or __delete__ — it takes priority over the instance's __dict__.

MRO & Metaclasses

C3 linearization and metaclasses are advanced topics that frequently appear in senior/architect interviews — especially in framework and ORM design contexts.

Method Resolution Order (C3 Linearization)

class A: def method(self): return "A"
class B(A): def method(self): return "B" + super().method()
class C(A): def method(self): return "C" + super().method()
class D(B, C): pass

print(D.__mro__)  
# (D, B, C, A, object) — C3 ensures consistent ordering
print(D().method())  # "BCA" — super() follows MRO

Metaclasses

# Metaclass — the "class of a class"
class RegistryMeta(type):
    _registry = {}

    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        if bases:  # skip base class itself
            mcs._registry[name] = cls
        return cls

class Plugin(metaclass=RegistryMeta): pass
class AuthPlugin(Plugin): pass
class CachePlugin(Plugin): pass

print(RegistryMeta._registry)
# {"AuthPlugin": <class AuthPlugin>, "CachePlugin": <class CachePlugin>}

# Modern alternative: __init_subclass__ (Python 3.6+)
class Plugin2:
    _registry = {}
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin2._registry[cls.__name__] = cls

A) Depth-first search

C) Breadth-first search
D) Topological sort
✓ Correct! Python uses C3 linearization (described in the paper "A Monotonic Superclass Linearization for Dylan") to compute MRO.

Design Patterns

Design patterns in Python often look different from textbook Java examples — leverage Python's duck typing, first-class functions, and Protocol for cleaner implementations.

Creational Patterns

# Singleton — using metaclass
class SingletonMeta(type):
    _instances = {}
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

# Factory — using registry dict
class ShapeFactory:
    _shapes = {}

    @classmethod
    def register(cls, name):
        def decorator(shape_cls):
            cls._shapes[name] = shape_cls
            return shape_cls
        return decorator

    @classmethod
    def create(cls, name, *args):
        return cls._shapes[name](*args)

@ShapeFactory.register("circle")
class Circle:
    def __init__(self, radius): self.radius = radius

Protocol — Structural Subtyping (Python 3.8+)

from typing import Protocol, runtime_checkable

@runtime_checkable
class Drawable(Protocol):
    def draw(self) -> None: ...

# No inheritance needed — duck typing with type safety
class Circle:
    def draw(self): print("O")

def render(shape: Drawable): shape.draw()
render(Circle())  # works — Circle satisfies Drawable Protocol

Generators & Iterators

Generators are memory-efficient powerhouses — understanding yield from and the full generator protocol is expected at senior level.

Iterator Protocol

# Custom iterator
class Countdown:
    def __init__(self, start): self.current = start
    def __iter__(self): return self
    def __next__(self):
        if self.current <= 0: raise StopIteration
        self.current -= 1
        return self.current + 1

# Generator function — simpler
def countdown(start):
    while start > 0:
        yield start
        start -= 1

# yield from — delegate to sub-generator
def chain(*iterables):
    for it in iterables:
        yield from it

list(chain([1,2], [3,4]))  # [1, 2, 3, 4]

Generator send() — Coroutine-style

def accumulator():
    total = 0
    while True:
        value = yield total   # yield sends total, receives next value
        if value is None: break
        total += value

acc = accumulator()
next(acc)          # prime the generator → 0
acc.send(10)       # → 10
acc.send(20)       # → 30

itertools Essentials

from itertools import islice, chain, groupby, product, combinations

# islice — take first N from infinite generator
def naturals():
    n = 1
    while True: yield n; n += 1

first10 = list(islice(naturals(), 10))

Context Managers

Context managers go far beyond file handling — they're the right tool for any resource that needs guaranteed cleanup.

__enter__ / __exit__ Protocol

import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self         # value bound to 'as' variable

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.elapsed = time.perf_counter() - self.start
        print(f"Elapsed: {self.elapsed:.3f}s")
        return False  # False = don't suppress exceptions

with Timer() as t:
    expensive_operation()
print(t.elapsed)

@contextmanager — Generator-based

from contextlib import contextmanager, asynccontextmanager, suppress

@contextmanager
def managed_transaction(session):
    try:
        yield session          # everything before yield = __enter__
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()        # everything after yield = __exit__

# suppress — silently ignore specific exceptions
with suppress(FileNotFoundError):
    os.remove("temp.txt")

# Multiple context managers
with open("a.txt") as a, open("b.txt") as b:
    data = a.read() + b.read()

Q: What arguments does __exit__ receive?

A) self, exception, traceback
B) self, exc_type, exc_val, exc_tb
C) self, error_code, message
D) self, context, result
✓ Correct! __exit__(self, exc_type, exc_val, exc_tb) — all three are None if no exception occurred. Return True to suppress the exception.

Threading & Multiprocessing

The GIL makes Python threading suitable only for I/O-bound work — for CPU-bound parallelism, use multiprocessing or asyncio.

Threading for I/O-Bound Work

from concurrent.futures import ThreadPoolExecutor, as_completed
import threading

# Thread pool for concurrent HTTP calls
def fetch(url): return requests.get(url).text

urls = ["https://example.com"] * 10
with ThreadPoolExecutor(max_workers=5) as pool:
    futures = {pool.submit(fetch, url): url for url in urls}
    for future in as_completed(futures):
        print(future.result()[:100])

# Thread-safe shared state
lock = threading.Lock()
counter = 0

def increment():
    global counter
    with lock:
        counter += 1

Multiprocessing for CPU-Bound Work

from concurrent.futures import ProcessPoolExecutor
from multiprocessing import Pool, shared_memory
import numpy as np

def cpu_heavy(n):
    return sum(i*i for i in range(n))

with ProcessPoolExecutor(max_workers=4) as pool:
    results = list(pool.map(cpu_heavy, [10_000] * 8))
GIL Warning
The GIL means only ONE thread executes Python bytecode at a time. Threading helps I/O-bound code (waiting on network/disk) but NOT CPU-bound code. Use multiprocessing or asyncio for true parallelism.

Q: Why does the GIL prevent true parallel threading for CPU-bound tasks?

A) Threads can't share memory in Python
B) Python threads are not real OS threads
C) Only one thread can execute Python bytecode at a time
D) The OS scheduler limits Python to one CPU
✓ Correct! The Global Interpreter Lock (GIL) ensures only one thread holds the interpreter at a time, serializing CPU-bound Python execution.

Asyncio & Async Patterns

Asyncio is Python's answer to high-concurrency I/O — understanding the event loop, structured concurrency, and pitfalls is essential for backend roles.

Core Asyncio Patterns

import asyncio
import httpx

# Concurrent requests with gather
async def fetch(client, url):
    resp = await client.get(url)
    return resp.json()

async def main():
    urls = ["https://api.example.com/users", "https://api.example.com/orders"]
    async with httpx.AsyncClient() as client:
        results = await asyncio.gather(*[fetch(client, u) for u in urls])
    return results

# asyncio.timeout (Python 3.11+)
async def with_timeout():
    async with asyncio.timeout(5.0):
        await slow_operation()

Task Management

# create_task — fire and forget with proper lifecycle
async def producer_consumer():
    queue = asyncio.Queue(maxsize=10)

    async def producer():
        for i in range(20):
            await queue.put(i)
        await queue.put(None)  # sentinel

    async def consumer():
        while True:
            item = await queue.get()
            if item is None: break
            await process(item)
            queue.task_done()

    await asyncio.gather(producer(), consumer())
Common Pitfall
Never call blocking code (like time.sleep(), synchronous DB calls, or CPU-heavy loops) inside an async function — it blocks the entire event loop. Use asyncio.sleep() and loop.run_in_executor() instead.

A) Runs coroutines sequentially one after another
B) Runs multiple coroutines concurrently and waits for all to complete
C) Creates a new event loop for each coroutine
D) Cancels all coroutines if one raises an exception
✓ Correct! asyncio.gather() runs all coroutines concurrently in the same event loop and returns their results as a list.

Memory Management & GIL

Production engineers must understand Python's memory model — reference counting, cyclic GC, and how to diagnose memory leaks.

Reference Counting

import sys, gc, weakref

# Reference counting
a = []
print(sys.getrefcount(a))  # 2 (a + getrefcount's argument)
b = a
print(sys.getrefcount(a))  # 3
del b
print(sys.getrefcount(a))  # 2

# Cyclic reference — NOT freed by refcount alone
class Node:
    def __init__(self): self.ref = None

n1, n2 = Node(), Node()
n1.ref = n2; n2.ref = n1   # cycle — gc module handles this
del n1, n2
gc.collect()               # explicitly run cyclic GC

# weakref — reference without incrementing refcount
class Cache:
    def __init__(self): self._store = weakref.WeakValueDictionary()

Secrets & Cryptography

import secrets, hashlib
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC
from cryptography.hazmat.primitives import hashes
import base64

# Secure token generation
token = secrets.token_urlsafe(32)   # 256-bit URL-safe token

# Secure password hashing with PBKDF2
def hash_password(password: str) -> str:
    salt = secrets.token_bytes(32)
    kdf = PBKDF2HMAC(algorithm=hashes.SHA256(), length=32, salt=salt, iterations=480_000)
    key = base64.urlsafe_b64encode(kdf.derive(password.encode()))
    return f"{base64.urlsafe_b64encode(salt).decode()}:{key.decode()}"

Database Patterns & SQLAlchemy

SQLAlchemy 2.x with async support is the standard for Python backends — understanding ORM pitfalls like N+1 and lazy loading is crucial.

SQLAlchemy 2.x ORM

from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship, selectinload
from sqlalchemy import String, Integer, ForeignKey, create_engine
from sqlalchemy.orm import Session

class Base(DeclarativeBase): pass

class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(50))
    orders: Mapped[list["Order"]] = relationship(back_populates="user")

class Order(Base):
    __tablename__ = "orders"
    id: Mapped[int] = mapped_column(primary_key=True)
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"))
    user: Mapped["User"] = relationship(back_populates="orders")

Fixing N+1 Queries

from sqlalchemy import select

# BAD — N+1 problem: 1 query for users + N queries for each user's orders
users = session.scalars(select(User)).all()
for user in users:
    print(user.orders)  # triggers lazy load for each user!

# GOOD — selectinload: 2 queries total (users + all orders in one query)
users = session.scalars(
    select(User).options(selectinload(User.orders))
).all()

# joinedload — single JOIN query (good for many-to-one)
orders = session.scalars(
    select(Order).options(joinedload(Order.user))
).all()
Connection Pooling
Always configure connection pooling for production: create_engine(url, pool_size=10, max_overflow=20, pool_pre_ping=True). pool_pre_ping=True validates connections before use — prevents "stale connection" errors.

Q: What does selectinload do differently from joinedload?

A) It loads all related data in a single JOIN query
B) It never loads related data until accessed
C) It uses a separate SELECT with WHERE IN instead of a JOIN
D) It caches results in memory between sessions
✓ Correct! selectinload fires a second SELECT ... WHERE IN (...) query — better for one-to-many (avoids row duplication from JOIN).

Architecture Patterns at Scale

Architect-level interviews focus on system design — Clean Architecture, DDD, CQRS, Event Sourcing, and microservices patterns in Python.

Clean / Hexagonal Architecture

Domain Layer (core business logic — no framework deps) ↕ Application Layer (use cases / services) ↕ Infrastructure Layer (DB, HTTP, messaging — implements interfaces) ↕ Ports & Adapters (FastAPI = adapter, SQLAlchemy = adapter)
# Domain — pure Python, no framework
from dataclasses import dataclass

@dataclass
class Order:
    id: str
    items: list
    def total(self): return sum(i.price for i in self.items)

# Port (interface)
from abc import ABC, abstractmethod
class OrderRepository(ABC):
    @abstractmethod
    async def save(self, order: Order): ...

# Adapter (SQLAlchemy implementation)
class SqlOrderRepository(OrderRepository):
    async def save(self, order: Order):
        await self.db.add(OrderModel.from_domain(order))

CQRS Pattern

# Command — mutates state, returns nothing (or minimal ack)
@dataclass
class CreateOrderCommand:
    user_id: str
    items: list

# Query — reads state, no side effects
@dataclass
class GetOrderQuery:
    order_id: str

# Separate read/write models — write uses ORM, read uses raw SQL for performance
class OrderCommandHandler:
    async def handle(self, cmd: CreateOrderCommand): ...

class OrderQueryHandler:
    async def handle(self, q: GetOrderQuery): ...

# ANTI-PATTERN: mutable default argument
def bad_append(item, lst=[]):
    lst.append(item)
    return lst

bad_append(1)  # [1]
bad_append(2)  # [1, 2] — NOT [2]! lst is shared

# FIX
def good_append(item, lst=None):
    if lst is None: lst = []
    lst.append(item)
    return lst

# ANTI-PATTERN: late binding closure in loop
funcs = [lambda: i for i in range(5)]
print([f() for f in funcs])  # [4, 4, 4, 4, 4] — oops!

# FIX: capture i at definition time
funcs = [lambda i=i: i for i in range(5)]
print([f() for f in funcs])  # [0, 1, 2, 3, 4]
