Module 1

Client-Server HTTP/HTTPS, DNS & Critical Rendering Path

Understand what happens when a user types a URL into their browser, the network layers involved, and how the browser constructs pixels from HTML, CSS, and JS.

1. The 5-Stage Network & Rendering Pipeline

  1. DNS Resolution: Browser checks in-memory cache -> OS hosts cache -> Local Resolver -> Authoritative DNS server to resolve hostname to IP.
  2. TCP 3-Way Handshake: Client SYN -> Server SYN-ACK -> Client ACK.
  3. TLS 1.3 Cryptographic Handshake: Key exchange, cipher suite negotiation, and server identity validation over HTTPS.
  4. HTTP GET & Response: Server returns HTTP headers (Status 200, Content-Type, Cache-Control) and HTML payload stream.
  5. Critical Rendering Path (CRP):
    • DOM Construction: Bytes -> Characters -> Tokens -> Nodes -> Document Object Model Tree.
    • CSSOM Construction: Parsing CSS into rules and style nodes (Render-blocking).
    • Render Tree: Merging visible DOM nodes with CSSOM computed styles.
    • Layout (Reflow): Computing exact geometry and coordinates on viewport.
    • Paint & Composite: Rasterizing layers to GPU and displaying pixels.
💡 Knowledge Checks & Common Interview Questions
Why is CSS considered render-blocking while JS is parser-blocking?▼
The browser cannot render the page before constructing the CSSOM because doing so would cause a flash of unstyled content (FOUC). JavaScript is parser-blocking because scripts can use document.write() or modify the DOM, so HTML parsing pauses when a synchronous <script> is encountered unless marked with defer or async.

function createCounter(initialValue = 0) {
  let count = initialValue; // Enclosed lexical environment

  return {
    increment: () => ++count,
    decrement: () => --count,
    getCount: () => count
  };
}

console.log(counter.getCount());  // 11

💡 Knowledge Checks & Common Interview Questions
Why does a resolved Promise run before setTimeout(..., 0)?▼
Promises are scheduled in the Microtask Queue, while setTimeout callbacks are placed in the Macrotask (Task) Queue. The JavaScript runtime drains all pending microtasks completely after every call stack execution before picking the next macrotask.

Fetch API, REST Integration & AbortController

HTTP requests with modern Fetch, error status handling, JSON parsing, timeout cancellation, and Promise.all concurrent requests.

1. Robust Fetch with Timeout & AbortController

async function fetchUserData(userId) {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 5000); // 5s timeout

  try {
    const res = await fetch(`https://api.example.com/users/${userId}`, {
      signal: controller.signal,
      headers: { 'Accept': 'application/json' }
    });

    if (!res.ok) {
      throw new Error(`HTTP Error: ${res.status} ${res.statusText}`);
    }

    const data = await res.json();
    return data;
  } catch (err) {
    if (err.name === 'AbortError') {
      console.error('Request timed out and was aborted.');
    } else {
      console.error('Fetch failed:', err.message);
    }
  } finally {
    clearTimeout(timeoutId);
  }
}

1. Debounce and Throttle Utility Implementations

// Debounce: Executes callback only after delay has passed since LAST invocation
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// Throttle: Guarantees callback runs at most once per time window
function throttle(fn, limit) {
  let inThrottle = false;
  return function (...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => inThrottle = false, limit);
    }
  };
}
